# 求解器架构

本文说明战斗求解器的整体结构、数据流与各模块职责。

## 0. 插件叫什么

求解器是一个 BepInEx 5 插件，仓库 `D:\Foreseeker` 有两个分支，**代码相同、身份不同**：

| 分支 | 插件 GUID | 显示名 | 配置文件名 | 产物 |
|---|---|---|---|---|
| `main` | `com.momeko.dd2.foreseeker` | `Foreseeker` | `Foreseeker.ini` | `Foreseeker.dll` |
| `Foretest` | `com.momeko.dd2.foretest` | `Foretest` | `Foretest.ini` | `Foretest.dll` |

- `main` 是正式版，默认隐藏所有窗口、关闭调试日志；
- `Foretest` 是测试版，日志全开，用于采集训练数据；
- 两者 GUID 不同，**同时启用会双重打补丁**，所以只保留一个生效（另一个改名 `.disabled`）。

目录结构：

```
D:\Foreseeker
├── src\                插件源码
├── tools\              fit-weights.py 等工具
├── docs\               本文档
├── README.md
└── build.cmd / src\build.ps1
```

## 1. 模块划分

| 模块 | 职责 |
|---|---|
| `Plugin.cs` | BepInEx 入口、窗口与 HUD、热键、ini、配置、敌方意图预测 |
| `Probe.cs` | Harmony 补丁：拦截游戏事件，转发给求解器 |
| `SaveReader.cs` | 读取游戏 CSV/po 数据，技能名、token 名、道途名、职业名 |
| `Solver.cs` | 核心：构建候选行、评分、排序、沙盘前瞻、写日志 |
| `SimState.cs` | 沙盘：快照、还原、模拟伤害/治疗/token/位移、泄漏检测 |
| `SolverProbe.cs` | 自动预演（实验性，默认关闭） |
| `RandomTrace.cs` | 随机数轨迹（调试用） |
| `ForetestLog.cs` | 日志文件管理（journey / debug） |

## 2. 数据流

```
游戏事件
   │  Probe（Harmony 补丁）
   ▼
Solver.Build(actor)
   ├─ 枚举候选（控制器条目 / 预计算结果回退）
   ├─ 每个候选 → Row（分数 + 分项）
   ├─ 排序
   ├─ 前瞻（沙盘）→ 还手惩罚
   └─ 再次排序
   ▼
HUD 显示 + 写日志（S DECIDE / TOP / FEAT / ACTUAL）
```

刷新频率约 0.7 秒一次，使用缓存避免重复计算。

## 3. 候选枚举

两条来源，按优先级：

1. **控制器条目**：`m_SkillTargetEntries`，即游戏认为合法的 (技能, 目标) 组合；
2. **预计算回退**：条目为空时，从 `m_PotentialResults` 反查该行动者的全部结果。

回退是必要的：回合刚开始的瞬间条目尚未生成，只靠条目会出现"只有跳过"的情况。

## 4. 评分模型

每个候选的分数是若干项之和：

| 项 | 含义 |
|---|---|
| `hp` | 造成的血量损失折算 |
| `kill` | 击杀奖励（我方被击杀为极大负值） |
| `eff` | 效果价值：token、DOT、治疗、压力 |
| `pos` | 位移收益（只算真正的 Move 效果） |
| `retal` | 还手惩罚（前瞻得出） |

另外还有四个**只用于记录、不参与当前评分**的特征（后续用于拟合）：

`tgtHp`（目标血量比例）、`threat`（该敌人预测伤害）、`allyDd`（我方死门人数）、`act`（目标本回合是否还会行动）。

兑换关系：

- 血量：按"损失占最大血的比例 × 5"计；
- 压力：1 点 1 分，超过 8 点后加速；
- 死门：约等于 +3 点压力，可接受；
- 英雄死亡**不可接受**，直接排除。

## 5. 沙盘（SimState）

游戏对象无法真正克隆（对象图、单例、事件总线），所以采用**快照 → 改真实对象 → 读取 → 还原**：

```
Capture()  → 保存队伍、行动者、token、状态、RNG
Apply*()   → 在真实对象上模拟（伤害、治疗、token、位移）
Peek*()    → 读取模拟后的结果
Restore()  → 全部还原
```

关键约束：

- **token 只写在覆盖层**，从不直接改真实容器；
- 护甲/次数用沙盒计数器，不调用游戏的增删接口；
- 位移用纯字段模拟，不调用游戏的排序方法；
- 每次还原后执行 `LeakReport`，任何残留都会写 `S LEAK`。

## 6. Boss 策略

| 场景 | 行为 |
|---|---|
| 普通战斗 | 完整前瞻 |
| 白名单 Boss（跛行者、收藏家、古董商人） | 完整前瞻 |
| 其它 Boss | 只评分、不预演，避免特殊 token 破坏镜像 |

## 7. 日志

| 行 | 含义 |
|---|---|
| `S BATTLE boss=…` | 战斗开始，含 boss 标记与排除标记 |
| `S DECIDE …` | 一次决策，含回合、行动者、候选数 |
| `S TOP1-3` | 前三名与分数、标签 |
| `S FEAT … \|v=2\|…` | 每个候选的特征向量（键值对，可扩展） |
| `S ACTUAL …` | 玩家实际选择，及其在当时的排名 |
| `S LEAK …` | 沙盘回滚失败 |
| `S TOKENUNKNOWN` | 未登记权重的 token |

文件：`BepInEx\plugins\<插件名小写>\journey-YYYYMMDD-HHMMSS-<原因>.log`，调试心跳写 `debug.log`。

## 8. 权重拟合

`tools\fit-weights.py`：解析 `S FEAT` + `S ACTUAL`，把每次决策转成排序约束，用 hinge 损失 + L2 正则求解权重。

流程：

1. 去重（同一回合重复记录只保留候选最全的一份）；
2. 丢掉排除样本、候选过少、选择不在候选里的决策；
3. 特征标准化；
4. 按战斗文件划分训练/留出集（避免近重复泄漏）；
5. 逐特征消融，只保留有贡献的。

## 9. 热键与配置

| 键 | 功能 |
|---|---|
| F5 | 求解器窗口 |
| F2 / F7 | 主 HUD |
| F9 | 状态窗口 |
| F10 | 预测窗口 |
| F3 / F4 / F11 | 回放、快照测试、应用测试 |
| F8 | 重置窗口位置 |

配置写在 `Foreseeker.ini` / `Foretest.ini`，改完不需要重启。

## 10. 已知限制

- 只有**一层前瞻**，对"两步组合"的收益判断不足；
- 敌方召唤、相位切换不做威胁折算；
- 评分是线性加权，不是真正的搜索；
- Boss 特殊机制下沙盘不可用，只能给出静态评分。

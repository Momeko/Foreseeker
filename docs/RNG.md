# 随机数（RNG）理解

本文记录我们对《暗黑地牢 2》随机数系统的逆向与使用方式。核心结论：**游戏的随机数是可保存、可恢复的命名流；预测的做法是"保存 → 抽取 → 还原"，而不是猜测。**

---

## 1. 命名流

游戏用 `RandomContainer` 管理随机数，每个 `RandomIdentifier` 对应**一条独立流**：

| 流 | 用途 |
|---|---|
| `SKILL_CALCULATION` | 技能预计算：暴击判定、伤害区间 |
| `RESIST` | 抗性判定（中毒、流血、眩晕、位移等） |
| `STRESS` | 压力增减 |
| `EFFECT` | 效果施加 |
| `TOKEN` | token 施加/消耗 |
| `DOT` | 持续伤害结算 |
| `ACTOR_CONTROLLER` | 敌方 AI（选技能、选目标） |
| `DEATHS_DOOR` | 死门判定 |
| `ACT_OUT` | 行动顺序相关 |
| `AFFINITY` | 好感度事件 |

流之间互不影响：消耗 `RESIST` 不会改变 `ACTOR_CONTROLLER` 的后续取值。

## 2. 快照与还原

```csharp
JObject state = container.SaveToJson();
// ... 任意抽取 ...
container.LoadFromJson(state);
```

这使"预读"成为可能：想预测下一步，就保存状态、抽几个值、再还原。玩家看到的游戏状态不会被改变。

## 3. 预测方式

### 3.1 敌方行动

`ACTOR_CONTROLLER` 流与玩家操作完全无关，敌方一次行动固定消耗两个值：

```
第 1 个值 → 按 m_RandomSelectChance 加权选技能
第 2 个值 → 在该技能的合法目标里等概率选目标
```

所以保存 → 抽 2 个 → 还原，就能得到**确定的**下一步行动。

### 3.2 抗性与伤害

抗性判定用 `RESIST` 流，每个效果一次抽取；伤害与暴击在 `SKILL_CALCULATION` 流里，每个 (技能, 目标) 组合消耗：

- 1 次暴击判定；
- 1 次伤害区间抽取。

多段攻击共享同一组结果。

## 4. 沙盘里的 RNG

求解器的沙盘（`SimState`）在快照时**同时保存所有 RNG 流**，回滚时一并还原。这样：

- 沙盘里执行的操作不会推进真实随机数；
- 同一局面反复预演，结果一致；
- 预演结束后，玩家的实际结算仍然使用原本的随机值。

## 5. 顺序敏感性

随机数的意义取决于**抽取顺序**。因此：

- 沙盘必须按游戏相同的顺序模拟（先暴击、再伤害、再抗性……）；
- 一旦我们的模拟顺序和游戏不同，后续所有数值都会错位；
- 所以求解器优先"读取游戏已算好的结果"，而不是自己重新抽取。

## 6. 校验手段

`RandomTrace` 可以在每次抽取时记录：

```
S RNG seq=1234 stream=RESIST value=0.42
```

开启后可以对比"我们预测的消耗"与"游戏实际的消耗"是否一致（`seq` 单调递增）。默认关闭，因为它会产生大量字符串分配。

## 7. 实践约束

| 约束 | 原因 |
|---|---|
| 只在玩家回合预演 | 敌方回合中控制器状态不稳定 |
| 预演必须成对（保存/还原） | 否则会推进真实随机数 |
| 不要在多线程里碰 RNG | 游戏本身是单线程 |
| Boss 特殊战默认关闭预演 | 特殊 token 无法完整镜像 |

## 8. 尚未确认

- 各流的底层算法（只需可保存/还原，暂不影响使用）；
- 是否存在"每次战斗重置"的额外种子；
- `AFFINITY` 等流在战斗外是否也会被消耗。

## 验证方式

- `SimState.Capture/Restore` 中的 RNG 快照代码；
- 日志中的 `S LEAK`（回滚失败检测）；
- 开启 `RandomTraceEnabled` 后的 `S RNG` 序列。
